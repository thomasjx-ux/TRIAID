Use scheduled GPT research runs to perform independently archived, genuinely forward-looking next-session SHADOW_ONLY validation for CN, HK and US. The GPT stream must not mutate Railway production Core, broker accounts, execution, existing freeze records, or any production evidence counter. If exact independently executable TRIAID Core is unavailable, report CORE_UNAVAILABLE; a language-only interpretation is not the same as running TRIAID.

## Authority and newest-discipline precedence
At each T0, inspect the repository's latest verified TRIAID_CONSTITUTION.md and applicable validated research discipline at or before T0. Record the exact commit SHA and discipline version in the new frozen record. Validated newer governance supersedes prior defaults *prospectively*; never rewrite older freezes or reinterpret old performance using a changed constitution. ## Market scheduling
CN: regular close 15:00 Asia/Shanghai; HK: regular close 16:00 Asia/Hong_Kong; US: regular close 16:00 America/New_York. Scheduled independent GPT T0 checks run on weekdays at CN 15:20 Asia/Shanghai, HK 16:20 Asia/Hong_Kong, and US 16:20 America/New_York. Every task checks the exchange's actual trading calendar and true close, including early closes; the schedule is only a trigger and does not guarantee that required final market data have settled. If data are unavailable, mark DATA_INCOMPLETE, do not freeze, and do not silently use a later outcome. Verify each exchange's official trading calendar, half days, suspensions and settlement of all required quotes independently; a scheduled weekday is not proof of trading. Skip closed markets. A stale or not-yet-settled close cannot enter a frozen next-session decision. If an execution is late after the target next session opens, mark LATE_EXCLUDED and never backdate it.

## Each market run
1. Resolve the most recent eligible previous frozen record and its targeted next actual exchange trading day; compare it against *actual independently sourced outcomes*, where all required products have complete settle-eligible daily data. Missing previous freeze => NO_PRIOR_FREEZE; missing results => PENDING. Do not turn pending into success or fill missing with the market's close.
2. Fetch complete current settled DAILY observations for the currently registered active and challenger strategy universe. Record source, quote timestamp, adjustment method, asset identifiers, missingness, corporate actions if applicable, data receipt time, trade calendar, portfolio accounting currency and source_mode. Historical INTRADAY/PREOPEN/REALTIME, L1/L2 and fills may not be inferred from DAILY.
3. Call the exact pinned, runnable TRIAID Core using frozen T0 inputs. When available, also execute the separately versioned read-only Value Frontier Shadow V2 as a challenger, never as production Core. Preserve pre-intervention weights, post-intervention weights, all excluded candidates and pre-specified rationale. If no executable version or full inputs, publish CORE_UNAVAILABLE or DATA_INCOMPLETE instead of fabricating weights or predictions.
4. Compare matched T0 baselines: current Core without TRIAID intervention; feasible competing strategy/strategy group available at T0; market beta benchmark appropriate to the traded universe; explicit cash/low-risk alternative; and any registered challenger. A T1 hindsight best is diagnostic only and must not be passed off as a selectable T0 baseline. Keep market, algorithm, strategy selection, dynamic weighting, and modeled execution cost contributions separate.
5. Create immutable T0 record for the NEXT actual exchange trading day in gpt_async_validation/ledger/{MARKET}/{YYYY-MM-DD}/decision.json. The dated record is an append-only GitHub create-file; if it exists, read and validate idempotently, NEVER update, delete or overwrite. Include freeze timestamp, source data effective timestamps, code commit, discipline version, executable status, strategy universe and exclusions, allocations, all baseline allocations, explicit evaluation metrics and 100k/1m/10m/100m model capital if input completeness permits. Preserve evidence links/source receipts and SHA-256 of canonical decision payload. If GitHub create-file or verification fails, mark UNFROZEN and do not count an experiment.
6. At T1 write gpt_async_validation/ledger/{MARKET}/{T0_DATE}/outcome.json as a new append-only create-file. Include independent realized T1 date, matching portfolio returns, net modeled costs, modeled capital P&L and percentage-point deltas per capital/capacity case, market versus algorithm attribution if identifiable, missed winners and binding T0 constraints, risk and latent-hazard changes, limitations, and all negative or inconclusive outcomes. Never backfill a missing freeze with later market data.

## Scientific gates and ongoing evolution
Compare paired prospective net compounded value under matched risk, liquidity, capacity, concentration, and realistic modeled cost; track drawdown degradation, turnover, and missing opportunities. Keep 20/60/120/250-trading-day windows, report raw paired count and missingness, and do not infer long-run alpha from a handful of sessions. Revisit model errors, run anti-leakage and false-success attacks, negative controls and independent holdout. Candidate promotion requires Replay, Holdout, Shadow, Audit and explicit user-approved release; this GPT stream never promotes or modifies the live Core. Where inference or exact code execution fails, explicitly preserve the failure state and research debt, and continue the next eligible run only with justified forward changes.

## Cross-market handling
CN, HK and US each use their own exchange local date/time and next trading day. Resolve separate T0/T1 windows; never treat another market's closure or weekend as a missing negative result. Cross-market causality is a hypothesis and must respect the actual information available at each freeze. Do not combine P&L in different currencies without recorded exchange-rate source and conversion timestamp.
